# Investment Strategy / Risk Agent 规格

决策及首版交付日期：2026-11-13（Asia/Shanghai）。V1首版已实现并接入父图。
当前范围为证据解释、约束检查与静态压力测试；估值情景和V2仍未实现。
实施步骤与实际验收见[strategy-agent-development.md](strategy-agent-development.md)。

## 职责与依赖边界

定位为有证据的策略解释、显式情景计算和约束检查，覆盖投资机会、未来情景、组合与风险解释。
V1不做自动选股，不引入复杂组合优化。报告子图内部及现有阶段输出展示保持不变。

- Market Data负责采集结构化数据，不在Strategy/Risk另建采集管线。
- Analytics负责历史收益、波动率、最大回撤、Beta、价格因子和估值比较。
- Strategy/Risk消费前置数据证据与分析产物，解释机会、假设、不确定性及用户约束。
- 数据依赖按任务需要规划，不要求所有策略问题都执行所有Analytics工具。
- 策略解释由LLM综合证据完成，不为“解释投资机会”额外创建只返回文本的工具。
- Skill可指导方法和工具选择；公式、数据检查、约束和计算保留在可测试的Python工具中。

## 工具清单与交付顺序

| 工具 | 职责 | 阶段与前提 |
|---|---|---|
| `evaluate_risk_constraints` | 结合持仓、已有风险指标及用户明确限制，检查仓位、集中度和风险约束，列出违规项 | V1核心；须有相应持仓、限制或风险输入 |
| `stress_test_portfolio` | 对明确持仓施加显式冲击，计算损失与集中风险 | V1核心，先做简单价格冲击；相关性变化等复杂冲击后续扩展 |
| `run_valuation_scenarios` | 根据盈利基数、增长及未来估值倍数等显式假设，计算情景价格和收益区间 | 盈利数据契约补齐后接入，不是首批工具的阻塞前提 |
| `optimize_portfolio` | 在权重、行业、换手等约束下计算组合，优先考虑最小方差等模型 | V2；数据、约束与具体模型支持需验证 |
| `allocate_risk_budget` | 按风险预算分配权重，风险平价与HRP作为不同配置方法分别评估 | V2；不将两者视为同一种优化算法 |
| `build_black_litterman_views` | 结合先验收益、明确观点与置信度，输出后验收益供组合配置使用 | V2后期，最后加入；具体接口待设计 |

首批实施两个核心工具：`evaluate_risk_constraints` 与简单价格冲击版 `stress_test_portfolio`。
State与交接设计见下节；具体V1实现与数值方法见末尾交付记录；后续工具契约仍待设计。

## 计算与解释约束

### 风险约束检查

复用Analytics已有数值，不重复建设单股波动率、回撤或Beta计算。
用户限制是判断约束是否满足的依据，例如“单股仓位不超过20%”。
没有明确限制时可以列出风险暴露和数据缺口，不能自行宣称适合用户或虚构风险阈值。
缺少持仓时不调用组合压力测试来代替单股机会分析。

### 情景与压力测试

事实数据与假设分开记录，并注明来源、日期、单位、计算口径与适用范围。
简单压力测试使用明确持仓和指定价格冲击，不把情景损失包装成发生概率或未来预测。

未来EPS乘以假设PE可形成估值情景，但当前PE/PB快照不足以支持完整盈利预测。
需先取得结构化EPS或可靠盈利基数；基数、日期或必要假设缺失时返回数据要求，不由模型编造。
情景价格和收益必须由确定性工具计算，不称为自动预测结果。

### 组合配置与库选择

PyPortfolioOpt、风险平价、HRP和Black-Litterman归Strategy/Risk，保持Analytics现有职责边界。
PyPortfolioOpt是候选实现依赖，并非全部模型均已验证可由它提供；
风险平价实现或其他库另行核实，HRP与Black-Litterman分别说明输入和方法。
不将历史平均收益默认视为可靠的未来预期收益。优化需明确约束、估计假设和失败/不可行条件。
本决策不安装新库或选择额外第三方数据API。

## 验收方向

实施遵循项目TDD和API隔离约定。后续测试至少覆盖：

- 约束满足、违反及未提供限制，且不虚构阈值。
- 简单价格冲击下的确定性组合损失、输入缺失和无效权重/冲击。
- 事实与假设可追溯，缺少盈利基数时返回数据要求。
- 复用上游产物，不重复采集或计算，不越过任务授权数据范围。
- 不需要组合工具的问题可正常完成策略解释；未接入功能不伪装成已执行。

用户已反馈此前提供的Analytics典型问题全部通过手动测试；这是这些场景的验收反馈，
不等于所有市场状态或未来Strategy/Risk工具已验证。


## State与父子图交接设计（2026-11-13，V1已实现）

采用独立StrategyState，不继承整个ParentState，不接收Analytics局部消息。
输入/输出使用独立Pydantic契约，内部State用于编排；通过适配层交接统一TaskResult。

| 分组 | 字段 | 语义 |
|---|---|---|
| 任务输入 | task、subjects、time_range | 本次问题、对象及投资期限，不混同数据观察日期 |
| 上游证据 | dataset_refs、analysis_refs、evidence | 本任务授权数据/分析引用，以及有来源的文本证据 |
| 用户与情景输入 | portfolio、risk_constraints、scenario_assumptions | 明确持仓、用户限制与显式情景假设 |
| 执行状态 | messages、tool_rounds、tool_calls_used、output_retries | 消息循环与有界调用/修正计数 |
| 产物与结果 | strategy_artifacts、tool_errors、result、status、error | 产物引用、工具失败信息及规范结果 |

messages使用消息reducer，其他字段通常由对应节点覆盖；后续若并行写入再单独设计合并规则。
完整时间序列和计算产物保留在请求级Store，State仅保存引用；
已采用独立StrategyStore保存规范工具产物并校验任务scope；不承诺跨请求持久化。

### 可选输入契约

portfolio可选：没有持仓仍可回答单股机会；需要组合检查/压力测试时才要求提供。
V1以权重统一表示持仓，须明确现金、计价币种及持仓日期；不把股数、金额和权重直接混用。
V1权重限于0–1，现金+持仓之和为1，不自动归一化，不支持杠杆；详见交付边界。

risk_constraints只记录用户明确给出的限制，例如max_single_asset_weight=0.2、
max_portfolio_volatility=0.15。未提供时保持缺失，不自动推断“中等风险偏好”或适合性。
各项检查注明指标口径和适用样本；历史最大回撤与阈值的比较不代表未来回撤可被保证。

scenario_assumptions与事实分开，每个情景包含名称、冲击/预测参数及来源，
区分user和agent_proposed。Agent提出的假设显式标记，不伪装成用户设定或市场事实。
简单价格冲击不扩充成未经依据的未来收益预测；V1来源枚举为user和agent_proposed。

### 规范结果契约

| 字段 | 内容 |
|---|---|
| summary | 对用户问题的直接回答 |
| opportunities | 机会判断及授权证据引用 |
| risks | 风险、证据与不确定性 |
| scenario_results | 确定性工具产物中的情景结果 |
| constraint_checks | 已检查、违反或无法检查的约束 |
| artifact_refs | 工具产物引用 |
| assumptions、limitations | 实际采用的假设与限制 |
| missing_information、missing_data_requests | 缺失说明与结构化补数据要求 |

数值结果在适配/校验层从规范工具产物重建，不直接信任LLM填报的数字。
LLM生成机会与风险解释，但须引用本任务授权证据或分析产物；不得借结果引用越权读取其他任务数据。

### 交接与状态语义

Supervisor组装当前任务输入和授权引用 → Strategy子图分析/工具执行/校验 →
适配层重建规范结果 → 统一TaskResult → Composer。
子图messages、计数器和Store对象不合并进父图，只有经适配的结果进入task_results。

技术异常为failed；存在有用结果但必要数据缺失时为partial。
单股机会解释不需要持仓时，不因portfolio缺失自动降为partial或failed；
用户请求组合压力测试而缺持仓时，保留其他可用结论并说明无法完成的部分。
无关可选输入缺失不等于任务失败，未执行的工具不得宣称已执行。

### State与交接验收

- 无持仓的单股解释可执行；组合任务缺持仓时明确返回缺失要求。
- 用户限制与Agent情景假设可区分，不填造阈值或用户偏好。
- 输入/引用越界或过期被拒绝；数值由实际产物重建，不能用LLM数字覆盖。
- 父图仅收到规范TaskResult，子图局部消息、Store和完整序列不泄漏。
- 部分可用结果与技术失败分别处理，报告内部保持不变。


## V1实际实现与剩余边界

步骤与代码导航见[实施规格](strategy-agent-development.md)。采用独立请求级StrategyStore，
工具产物按每次策略执行scope隔离并绑定规范输入，结果在子图与Supervisor边界重建。
父图状态只有TaskResult，没有Store对象、局部消息或完整序列。Strategy产物引用包含小规模检查结果和输入来源以便追溯。

- 持仓首版仅CNY多头，权重0–1，现金+持仓之和在绝对误差1e-8内等于1，禁止重复代码和非有限数值。
  不自动归一化，不支持杠杆/做空或FX。明确日期接收ISO字符串。可选null限制/情景按省略处理，其他非法类型仍拒绝。
- 约束支持max_single_asset_weight、max_asset_annualized_volatility、max_asset_drawdown；
  单股历史风险只读取analyze_price_performance产物的fraction口径，并携带实际分析区间和来源ID。
  有持仓日期时不使用晚于该日期的样本，币种须兼容；多份产物取最晚end_date，未实现复杂研究窗口匹配。
  max_portfolio_volatility/max_portfolio_drawdown无组合估计时为unknown，不把单股数值聚合成组合风险。
- 空约束不产生适合性判断。全部现金时单股仓位暴露为0；现金静态冲击收益为0。
- 压力收益为权重×冲击之和；冲击需且仅覆盖所有持仓，跌幅不低于-100%，现金不参与价格冲击。
  user/agent_proposed来源随产物显示，不推断概率、不含费用/再平衡/FX或相关性变化。
- 所有实际工具结果都进入规范输出，不允许模型省略违规项；解释必须引用授权ID。
  引用校验不等于语义真实性证明，LLM文字质量仍需人工/模型评估。
- 无有效证据或持仓时返回partial补数据要求；原始工具返回unavailable不视为有效事实来源。
- 固定methodology文件已接入research_skills/strategy-methodology/SKILL.md；不授权外部操作。
- Planner参数、父图/response_graph、Composer及UI已接入；报告内部不变。
- 尚未实现：EPS/盈利采集扩展、估值情景、组合优化/风险平价/HRP/Black-Litterman、动态重规划和持久化。

测试使用mock模型/API及真实确定性工具；另有一条测试假设组合的真实模型链路抽查，
Planner两次尝试后完成两个策略任务，60%/30%/10%组合在-20%/-10%冲击下返回-15%，
并检出60%仓位超过50%用户上限。未调用行情接口；不是广泛真实模型质量或浏览器视觉验收。


## 回撤约束链路失败保护（2026-11-13）

用户实测Analytics正确生成历史回撤，但Strategy任务失败，最终回答仍给出超限判断。
已有strategy_result曾把所有子图失败统一变成strategy_failed，无法据旧日志确定原始触发原因。
使用本地测试价格产物+真实模型重放策略阶段成功，未稳定复现用户当次失败；不能断言是某个特定工具/引用错误。

本轮明确修正：
- 适配层保留白名单内的应用错误码和安全提示，未知错误仍采用通用错误，不透传供应商异常。
- Strategy初始化/输出校验发strategy_diagnostic自定义事件，复用安全字段诊断并在执行记录展示。
- 确定性工具已有规范产物时，解释模型失败、重复调用或输出修正耗尽返回partial并重建计算结果，
  missing_information记录解释未完成；不引用无效LLM结论。没有规范产物的技术失败仍failed。
- 首轮显式约束/情景工具执行后，解释阶段不再绑定工具，避免正常解释重复计算。
- Strategy若failed/blocked/unsupported，Composer直接使用确定性逐任务结果作为fallback，
  不再让汇总模型替代失败专家自行完成阈值检查。
- 提示明确年化频率不决定最大回撤；非总回报口径不自动证明回报低估，禁止推断偏差方向。

全量364单元测试通过，结构lint与diff检查通过；覆盖模型失败仍保留回撤检查、错误码、字段诊断UI及汇总隔离。
原报告内部不变。该修正提高可用性与可观测性，不宣称旧失败的精确原因已经被证明。


## 纯策略解释的工具适用性修正（2026-11-13）

用户提供的双股表现+估值链路日志显示：没有持仓、限制或情景时，首次解释仍绑定两个工具，
模型无意义地调用evaluate_risk_constraints得到空检查，再请求未注册工具而触发tool_scope_error。
已有计算/引用交接成功；旧日志没有记录被拒绝的具体工具名，不臆测名称。
上一轮仅关闭了“工具执行后的解释”绑定，未覆盖“从未需要工具的首次解释”，本次补齐。

V1工具选择完全由显式输入决定：用户约束触发风险检查，持仓+情景触发压力测试，
仍由ToolNode执行并受预算/参数/作用域校验。之后以及纯证据解释阶段LLM均不绑定工具。
若提供方仍返回tool_calls，不执行、不把未匹配工具消息塞入历史；记录安全工具名诊断，
由finalize统一使用既有输出修正预算。修正成功可completed；耗尽且已有规范计算则partial保留结果，
无计算产物则failed，不放宽工具白名单。

同时提示Analytics/Strategy/Composer：PE/PB差异不能单独证明成长性、资产重估或市场定价原因，
缺少基本面证据时仅描述差异，原因标为待验证假设；该提示不等于语义质量已被程序证明。
新增回归覆盖无约束纯解释不绑定工具、未注册请求安全修正、双股表现+估值三份分析产物直接解释。
没有调用真实行情或新增模型抽样；报告内部不变。


## 纯解释引用字段混淆的复现与修正（2026-11-13）

用户再次报告纯机会分析invalid_output。用相同问题、本地双股价格/估值计算产物和真实模型重放，
明确复现一种失败：模型把上游analysis_ ID填入StrategyAnswer.artifact_ids，而该字段只允许当前scope的strategy_工具产物。
纯解释没有执行策略工具，因此合法artifact_ids为空。旧修正仅反馈空artifact_id列表，未指出字段含义，
模型第二次原样返回，最终失败。该重放证明这个具体失败模式，不假定无原始响应的历史失败全部同因。

修正：
- 模型侧strategy_answer_schema移除artifact_ids；已执行工具产物由代码选择和重建。
  运行时StrategyAnswer保留兼容字段，但错误/未知引用仍拒绝，不把analysis ID悄悄转为策略产物。
- 每次解释与修正提供分类引用清单：dataset_ids、analysis_ids、有效evidence_ids、strategy_artifact_ids；
  明确上游分析应填opportunities/risks的evidence_ids，纯解释没有strategy产物是正常状态。
- StrategyReferenceError提供reference_scope字段诊断、修正提示和尝试次数；不再把引用错误当成空诊断。
- 追加到模型的工具产物摘要不复制完整inputs，避免不必要的重复上下文。

修正后的真实模型重放首次通过结构/引用校验，因本地样本短且缺基本面返回partial，无执行错误。
这不是使用用户原有真实日线数据的端到端重跑，也不证明生成文字的经济推断全部正确。
测试继续覆盖错误字段能被修正、非法引用仍拒绝、纯解释无需策略工具；报告内部保持不变。

用户场景与后续能力建议另见[常见策略提问与扩展参考](strategy-user-questions-and-expansion.md)。
该参考区分已实现能力、已确认范围与待评估建议，不自动授权实现全部扩展。
