# Strategy 用户问题与能力扩展参考

整理日期：2026-11-13（Asia/Shanghai）。用途：保存讨论，供产品规划、工具设计与后续验收参考。
这是一份场景分类与扩展建议，不是用户频率统计，也不是所有后续功能的实施承诺。
当前已实现范围以[Strategy/Risk规格](investment-strategy-agent.md)为准；开发经验见[实施步骤](strategy-agent-development.md)。

## 1. 常见问题类型与当前覆盖

| 类型 | 典型问题 | 当前覆盖 | 主要缺口 |
|---|---|---|---|
| 投资机会与风险 | 茅台未来一年有什么机会和风险？ | 部分支持：结合已获取估值、历史表现及证据做定性解释 | 基本面历史、最新经营变化、盈利预期与催化因素 |
| 标的比较与选择 | 茅台和五粮液哪个更值得关注？ | 部分支持：比较PE/PB、收益、波动率和回撤，解释差异与限制 | 盈利质量、增长、行业/同业基准；不能仅凭现有指标断言未来赢家 |
| 买卖时机与目标价 | 现在能买吗？什么价买？什么时候卖？ | 能提供已有数据背景，尚不足以提供经过验证的择时或目标价 | 估值情景、用户条件、判断失效条件；交易信号还需规则与回测 |
| 持仓与风险管理 | 仓位是否集中？是否超过我的风险限制？ | 支持单股仓位、已有单股历史风险阈值检查 | 组合波动率/回撤估计；不以单股风险冒充组合风险 |
| 情景与压力测试 | 两只股票分别跌20%和10%，组合亏多少？ | 支持明确持仓下的静态价格冲击 | 盈利×估值情景尚未实现，复杂相关性/路径冲击不在V1 |
| 组合配置与调整 | 各配多少？如何降低风险？ | 尚未支持优化计算 | 优化约束、风险预算、预期收益估计与模型验证 |

“已接入Agent”不等于完整投研判断能力。当前最可靠的基础是确定性历史计算与明确输入下的风险检查。
定性解释可用，但引用合法不代表文字推断已经得到事实支持；真实模型与端到端仍需持续验收。

## 2. 已确认的职责与工具范围

- Market Data采集结构化数据与来源证据。
- Analytics计算历史表现、基准、价格因子与估值差异。
- Strategy/Risk使用前置证据解释机会/风险，检查用户限制并运行显式情景。
- 公式、参数检查和数值运算在Python工具；方法指导可用固定methodology skill。
- 普通单股解释不要求持仓，不为使用工具而创造限制或冲击情景。

| 工具 | 当前状态/范围 |
|---|---|
| evaluate_risk_constraints | V1已实现：明确仓位/单股风险阈值；组合风险无估计时返回无法检查 |
| stress_test_portfolio | V1已实现：CNY多头、明确权重/现金/日期，静态价格冲击 |
| run_valuation_scenarios | 后续扩展方向，尚未实现；盈利基数和口径前提须先补齐 |
| optimize_portfolio | V2计划方向，尚未实现 |
| allocate_risk_budget | V2风险预算/风险平价方向，HRP作为不同配置方法评估 |
| build_black_litterman_views | V2后期方向，先验/观点/置信度及接口仍需设计 |

PyPortfolioOpt是候选实现库，不预设覆盖所有方法；风险平价、HRP与Black-Litterman分别核实。
不将历史平均收益默认当作可靠未来预期收益。工具名是当前设计名，扩展接口仍需实施规格和测试。

## 3. 对前三类问题最有价值的补充

以下是讨论中的推荐优先级，记录供后续选择；尚未授权或实施整套数据扩展。

### 优先一：盈利质量与变化的数据链

建议采集最近3–5个完整年度及近期季度，先覆盖：

- 营收、归母净利润、扣非净利润及相应增长。
- EPS、ROE、利润率与经营现金流。
- 现金、债务/负债等财务风险信息。

数据保留报告期、公告/可用日期、来源、币种与单位，区分累计/单季度、年度/TTM、修订记录与适用范围。
不直接比较不同口径，不把后来公布的数据当作当时已知数据。
建议再建设增长/盈利质量比较工具，由Analytics确定性计算，Strategy解释有据可查的差异。
数据源候选可评估现有AKShare与Tushare，权限、覆盖、字段和稳定性须实际验证，未决定更换供应商。
参考：[Tushare财务指标官方接口](https://tushare.pro/document/2?doc_id=79)。

### 优先二：最新公告与经营变化证据

补充财报、业绩预告及经营公告，必要时增加行业信息。记录事件日期、披露日期与原文出处，
明确事实与解释，判断增长、利润率、现金流是否正在变化，以及哪些事件可能改变原判断。
券商盈利预测可后续评估，须带预测年度、更新日期、来源/覆盖等信息，与已披露事实分开。
不把新闻存在或券商观点直接当作确定未来收益的证据。

### 优先三：历史估值背景与条件估值

历史估值区间/分位提供背景；需明确指标定义、窗口及历史数据可用性，不单凭分位判断便宜或贵。
EPS×PE情景帮助回答“在什么假设下，这个价格有吸引力”，而不是自动预测目标价。

### 优先四：用户决策条件

明确投资期限、现有持仓、目标收益和可承受损失，不自动推断风险偏好。
在有数据和方法支持时组织条件式讨论：什么价格/盈利假设满足目标、什么变化使判断失效、
什么仓位超出用户限制。条件式讨论不等于经验证的交易信号。

推荐推进链路：基本面契约与采集 → 增长/盈利质量比较 → 公告证据交接 → 估值情景。
这比先增加更多技术指标或复杂优化更直接覆盖机会分析、标的比较与价格讨论；优先级仍是建议。

## 4. EPS×PE估值情景的讨论方案

状态：讨论方案，尚未实现；这里保存范围建议，不把它写成已交付功能。
首版建议单股、正EPS、EPS×PE，不包含DCF、股息预测或概率加权。

### 数据与参数前提

| 输入 | 要求 |
|---|---|
| 基期EPS | 来源、报告期、公告/可用时间、币种、每股单位、年度/TTM口径 |
| 参考价格 | 来源、观察日期、币种、复权与每股口径 |
| 盈利增长假设 | 年增长率、期限，区分user和agent_proposed |
| 期末估值假设 | 明确期末PE；属于情景参数，不是事实或默认预测 |
| 股本口径 | EPS和股价每股口径兼容，关注拆分/股本变化 |

当前PE/PB快照不足以替代盈利数据。默认不使用“股价÷PE”反推EPS；未来若支持必须标为推导数据并校验口径。
用户提供EPS/参考价格的离线计算入口值得支持，但须先定义独立的来源与输入契约，不能默认已支持。

### 确定性计算

```text
情景EPS = 基期EPS × (1 + 年增长率)^年数
情景价格 = 情景EPS × 期末PE
价格收益 = 情景价格 ÷ 参考价格 − 1
```

只在输入有效、口径兼容时计算；非正EPS、缺失基数或不兼容单位返回明确原因。
例：EPS为10元、参考价200元，一年增长8%、期末PE20倍，对应216元与8%价格收益。
不含股息、费用或税费，不赋予发生概率，也不是收益承诺。

建议流程：Market Data盈利/价格引用 → Strategy保留显式情景 → 确定性工具 → Strategy/Composer解释。
工具从授权引用读取事实基数，不让LLM用参数悄悄改写。结果复用请求级StrategyStore。
展示可先用情景表，再加增长率×期末PE敏感性热力图；热力图属于额外展示任务。
建议实施顺序：盈利契约/采集 → 计算工具与隔离测试 → Strategy接线 → 情景表/热力图。

### 未来可测试的问题

- 假设茅台一年EPS增长8%、期末PE20倍，情景价格及相对参考价格收益是多少？
- 为茅台比较三种情景：EPS下降5%/PE18倍，增长5%/PE20倍，增长10%/PE23倍。
- 五粮液EPS增长10%、PE降到18倍时，盈利增长能否抵消估值收缩？
- EPS下降10%、PE维持参考倍数，情景价格变化多少？
- EPS增长率−10%/0%/10%与PE15/20/25倍组合下，价格和收益如何变化？
- 不查行情，用户明确提供EPS10元、参考价200元，计算一年增长8%、PE20倍的情景。

这些是未来验收样例，不代表现在可以调用尚未实现的工具。
用户只问“一年后涨到多少”时，应要求补充假设或给出明确标注的探索性假设，不能伪装成预测。

## 5. 买卖时机与目标价仍需额外能力

盈利/公告/情景能支持条件式决策讨论，但不能单独产生经过验证的买卖时点。
若后续提供交易信号，需独立定义规则、含交易成本的回测和样本外评估，防止前视和过拟合。
当前不承诺“最优买入价”“未来赢家”或上涨概率。无证据时说明缺口，不以LLM文字补足模型能力。

## 6. 后续设计时的检查清单

1. 这个问题缺事实数据、计算方法、用户条件，还是三者都缺？
2. 数据由Market Data取得，计算由Analytics/Strategy合适的工具完成了吗？
3. 报告期/公告日、单位、复权和每股口径是否可比？
4. 情景假设与来源是否显式，是否错误声称为事实/预测/概率？
5. 模型生成的结论是否真正有证据支持，而不只是引用ID合法？
6. 缺失时是否保留可用结果并说明限制，尚未实现的功能是否明确标记？
