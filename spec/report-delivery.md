# 报告阅读与下载

决策日期：2026-11-13（Asia/Shanghai）。
当前交付：生成后在同一Streamlit会话立即阅读和下载。其余内容为后续扩展，不在本轮实现。
本规格更新此前“报告正文与下载暂时隐藏”的UI决定；报告生成子图内部及C1–C9不变。

## 首版范围与用户流程

1. 用户提交明确的报告请求，沿现有父图调用report子图。
2. 报告任务终止后，在“报告中心”页签查看成品，四个阶段输出继续留在“节点结果”。
3. 可下载UTF-8 Markdown或独立HTML；HTML含内置样式，可在本地浏览器打开阅读。
4. 仅使用已经生成的final_report，不为阅读、下载或页面重绘再次调用LLM/数据API。
5. 本轮多报告按task_id分别展示、下载；新请求替换最近结果，新对话清空当前结果。

不新增数据库、对象存储、外部发布接口、公开访问权限或单独API后端。
当前不是可长期分享的报告链接；session_state不等于持久化，刷新/断线或服务重启后可能无法恢复。
下载的文件由用户在本地保留。

## 展示与导出

- 展示主题、行业、研究期限、报告日期、模型评级、投资论点、四维度分析、支撑证据、风险和来源。
- 模型分析置信度明确区别于未来收益/事件概率，不把报告评级变成系统执行的交易建议。
- completed/partial任务才进入报告阅读；failed/blocked等任务只保留节点信息，不作为成品导出。
- 部分完成或validate_report未通过的内容明确为草稿，文件名带draft，导出文件内同样注明。
- 无法解析的报告给出提示，不让前端崩溃，不直接展示任意原始字符串。
- C1–C7校验只调用现有validate_report，不另写业务校验规则；展示层做格式防御。
- 对生成文本作HTML/Markdown转义，来源仅将有效HTTP(S)链接变成超链接。
- 不把报告正文送入Composer重新改写；Composer仅提示状态和阅读/下载位置。
- 当前不从报告文字猜数字生成图表；后续图表必须来自明确关联的结构化数据/计算产物。

实现：app/report_viewer.py负责准备、Markdown/HTML格式化及阅读；app/streamlit_app.py接入页签。报告生成节点位于默认收起的开发者调试区，不与成品阅读混放。
没有改report_graph或报告各节点提示、工具、校验循环。没有处理已暂缓的Strategy invalid_output问题。

## 后续扩展（尚未实现）

打开链接不重新生成报告。需先实现报告保存、查找、找不到/删除/版本处理。

### 持久化与部署

可评估数据库保存ID、标题、日期、结构化正文及访问控制；有大文件时再增加对象存储。
不把Streamlit Community Cloud的本地runtime/reports目录作为可靠长期报告库。
Streamlit应用可以作为部署入口，独立后端仅在需求需要时另评估；本轮未部署。
云端仍需验证行情源可达性、模型secrets、依赖、并发和导出能力。
存储供应商、权限模式、保留期限、报告版本策略及费用均待定。

### PDF、图表与排版

后续可在报告阅读页加入真实结构化数据驱动的Plotly图表，不伪造价格/量化结果。
